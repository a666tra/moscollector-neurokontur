# Москоллектор.НейроКонтур

Локальный прототип для анализа телеметрии инженерных коллекторов: ранжирование каналов по proxy-разметке будущих отклонений, демонстрация правил фильтрации и формирование черновиков заявок на обслуживание.

Это демонстрационный стенд. Он не подключён к SCADA/СМВУ или CMMS заказчика. Карта, потоковые сценарии и статусы в интерфейсе не подтверждают реальные аварии, ремонты, отменённые выезды или достигнутую экономию.

## Запуск локального прототипа

```bash
docker compose up --build
```

После запуска откройте `http://localhost:8000`; документация API доступна по `http://localhost:8000/docs`.

```powershell
.\run_local.bat
```

```powershell
pip install -r requirements.txt
cd frontend
npm.cmd install
npm.cmd run build
cd ..
python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

## Данные и интерпретация меток

Предоставленный набор не содержит внешнего журнала подтверждённых ремонтов CMMS/1С:ТОИР. Поэтому целевая переменная построена алгоритмически по будущим физическим отклонениям телеметрии в окне 24–72 часа. Это proxy-разметка для эксперимента с ранжированием, а не перечень подтверждённых отказов или аварий.

Для отложенной проверки использованы 11 485 каналов и 174 proxy-positive канала с целевыми событиями телеметрии 29–31 января при cutoff 28 января. Эти случаи нельзя называть реальными ремонтами или предотвращёнными авариями. Сверка примеров в `backend/data/reconciliation_ground_truth.json` возвращает proxy TP/FP/TN на исходных строках телеметрии; генератор — `python -m scripts.build_reconciliation_json`. Результаты сверки не доказывают факт ремонта.

Для немедленной автономной проверки и локального запуска без необходимости загрузки внешнего архива телеметрии (1,5 ГБ) в комплект поставки включён компактный калиброванный датасет: [`dataset/sample_synthetic_telemetry.csv`](dataset/sample_synthetic_telemetry.csv) (1 000 строк телеметрии, 46,9 КБ) с документацией полей в [`dataset/README.md`](dataset/README.md). Он сгенерирован генератором `python scripts/generate_synthetic_sample.py` на основе физических диапазонов датчиков коллекторов (метан CH4, угарный газ CO, уровень затопления, температура силовых кабелей 10–220 кВ, охранный периметр) и позволяет выполнять сквозную проверку модулей скоринга и симулятора в полностью изолированном контуре.

Карта использует демонстрационную параметрическую топологию и пикетаж. Её координаты и маршруты не являются рабочей GIS-картой коллектора и не подходят для навигации бригад.

Потоковый фильтр и симулятор показывают работу на сценариях прототипа. Доля «отфильтрованных ложных тревог» по подтверждённой выборке не измерена, поэтому процент снижения тревог не заявляется.

## Расчётная экономика

Фактические выезды, подтверждённые ложные тревоги, тарифы работ и достигнутая экономия в рамках хакатона не измерялись. Экономический эффект (42,2–56,9 млн ₽/год) — это нормативно-сценарная модель (18 500 ₽ экстренный выезд vs 3 200 ₽ регламентное ТО при 230–310 предотвращённых инцидентах в месяц) для демонстрации потенциала окупаемости решения. Пример формулы:

```text
годовой сценарий = (стоимость экстренного выезда − стоимость плановой проверки)
                   × предполагаемое число случаев в месяц × 12
```

Вводные `18 500 ₽`, `3 200 ₽` и диапазон `230–310 случаев в месяц` являются нормативно-сценарными допущениями для демонстрации механики расчёта, а не подтверждёнными расценками или статистикой заказчика. Фактический экономический эффект требует интеграции данных 1С:ТОИР / CMMS и подтверждённых исходов выездов дежурных бригад ОДС АО «Москоллектор». Получаемые расчётные значения не учитывают совокупную стоимость владения (TCO), расходы на внедрение и эксплуатацию и не означают гарантированную фактическую экономию, ROI или подтверждённый срок окупаемости.

## Что показывает прототип

- Ранжирование каналов по ML-оценке на proxy-метках.
- Локальную симуляцию тестовых сценариев телеметрии.
- Кандидатов на разбор диспетчером и демонстрационный PIN-процесс подтверждения.
- Черновики заявок на обслуживание и журнал решений в локальном хранилище.
- Демонстрационную карту без рабочих координат.

Выбор диспетчера и PIN в демо не являются полноценной многофакторной аутентификацией, интеграцией с корпоративным каталогом или подтверждением соответствия ГОСТ. SHA-256 журнал показывает технический механизм прототипа, а не сертификацию или аудит системы.

Методика ОПЭ зафиксирована строго как проект научно-технической программы будущей опытно-промышленной эксплуатации, а НЕ как уже проведённый эксперимент. Подключение к SCADA/СМВУ, CMMS, промышленная аутентификация, проверка регламентов и оценка безопасности остаются предметом планируемого пилота с заказчиком. В репозитории есть API для локального прототипа, но нет действующей интеграции с системами АО «Москоллектор».

## Проверка проекта

Запустить имеющиеся автоматические проверки API:

```powershell
python -m pytest tests/ -v
```

Команда запуска обучающего пайплайна:

```powershell
python backend/ml/train_validated_model.py
```

В проверочном прогоне API, ML-калибровки и синтетического пайплайна прошло **52 теста, 0 пропусков**; отмечено одно предупреждение Starlette. Тесты сами создают одноразовый локальный реестр и PIN, поэтому отдельные credentials для этого прогона не нужны.

### Воспроизводимость метрик из кэша признаков

Для мгновенной независимой проверки всех ML-метрик без необходимости скачивания исходного 1,5 ГБ CSV используется 2-уровневая архитектура (подробно см. [`docs/DATA_PROVENANCE_AND_REPRODUCIBILITY.md`](docs/DATA_PROVENANCE_AND_REPRODUCIBILITY.md)):
- **Уровень 1 (сырые данные):** `dataset/extracted/ext-journal-2026.csv` (1,49 ГБ, SHA-256 `4dbbb106...`) извлекается скриптом `train_validated_model.py` с созданием кэша признаков.
- **Уровень 2 (автономный кэш):** `backend/data/extracted_features_cache.npz` (SHA-256 `65871b3b...`, включён в релизный архив).

Команда воспроизведения метрик и динамических инвариантов:

```powershell
python scripts/reproduce_metrics.py
```

Скрипт проверяет SHA-256 кэша признаков, рассчитывает Brier Score и ECE для всех моделей, выполняет чемпионскую beta-калибровку (а также сравнивает с legacy Platt и prevalence baseline), вычисляет метрики когорты высокого риска и Top-K каналов, динамически проверяет сходимость матриц ошибок по всем инженерным подсистемам и обновляет `backend/models/metrics_report.json`.

### Локальная demo-учётка

Рабочие demo-учётки в Git не поставляются. Для авторизованной демонстрации создайте локальный игнорируемый файл `backend/data/authorized_dispatchers.json` интерактивной командой:

```powershell
python scripts/provision_dispatcher.py --clearance-level 3 --can-confirm-false-alarm --can-force-dispatch
```

Команда запрашивает badge, имя, роль и PIN дважды без отображения PIN; он сохраняется как salted PBKDF2-HMAC-SHA256 hash. Не передавайте PIN в аргументах командной строки и не публикуйте файл. Без локального реестра операции, требующие авторизации, закрыты. Для Docker Compose выполните provisioning до `docker compose up --build` либо перезапустите сервис после создания файла; локальный реестр не включается в образ.

### Данные сверки и воспроизводимость

Для независимой перепроверки строк требуется исходный CSV от организаторов по пути `dataset/extracted/ext-journal-2026.csv` (файл объёмом ~1,5 ГБ не включён в Git). Сверьте его SHA256 со значением `source_journal_sha256` в `backend/data/reconciliation_ground_truth.json`, затем выполните:

```powershell
python -m scripts.build_reconciliation_json
```

Без внешнего CSV поставляемый JSON со сверкой доступен в репозитории, но независимо проверить исходные строки нельзя. Для быстрой функциональной проверки пайплайна загрузки и анализа без внешнего CSV используйте включённый в репозиторий файл [`dataset/sample_synthetic_telemetry.csv`](dataset/sample_synthetic_telemetry.csv).
