# Чек-лист сдачи по §19 ТЗ

§19 ТЗ просит указать четыре ссылки: на репозиторий с кодом, презентацию, прототип и сопроводительную документацию в DOCX/PDF. Пути ниже подтверждают наличие локальных материалов, но их нельзя вставлять в форму вместо внешних ссылок.

## Локально подготовленные материалы

| № | Требование §19 | Файл или локальная проверка |
|---|---|---|
| 1 | Репозиторий с кодом | Исходный код находится в корне репозитория. Собрать ZIP: `python scripts/export_release_bundle.py`. Результат: `release/Moscollector_NeuroKontur_Solution_Bundle.zip`; контрольная сумма создаётся рядом как `release/Moscollector_NeuroKontur_Solution_Bundle.zip.sha256`. Каталог `release/` и sidecar не входят в ZIP. |
| 2 | Презентация | [PDF](../presentation/Москоллектор_НейроКонтур_Защита.pdf) и [PPTX](../presentation/Москоллектор_НейроКонтур_Защита.pptx). |
| 3 | Прототип | Backend: [`backend/app/main.py`](../backend/app/main.py); интерфейс: [`frontend/dist/index.html`](../frontend/dist/index.html). Локально запускается `docker compose up --build`, затем открывается `http://localhost:8000`. Этот адрес работает только на компьютере, где запущено приложение. |
| 4 | Сопроводительная документация (.docx/.pdf) | [PDF](Пояснительная_записка_Москоллектор_НейроКонтур.pdf) и [DOCX](Пояснительная_записка_Москоллектор_НейроКонтур.docx). |

## Проверка релизного архива

После завершения изменений в исходном коде, модели, метриках и документах выполните из корня проекта:

```powershell
python scripts/export_release_bundle.py
python scripts/verify_unpacked_bundle.py
```

Первый скрипт пересобирает ZIP, проверяет состав и записывает SHA-256 в отдельный файл `.zip.sha256` после успешной проверки. README и паспорт входят в ZIP, поэтому их содержимое не должно заявлять хэш самого ZIP. Второй скрипт сверяет sidecar, проверяет наличие локальных материалов всех четырёх пунктов §19 в распакованном комплекте, затем выполняет имеющиеся проверки автономной сборки.

## Поля для копирования в форму

Замените текст в квадратных скобках фактической ссылкой после публикации или развёртывания. Сейчас в проектных документах внешние URL не заявлены; незаменённый шаблон нельзя отправлять.

```text
1. Ссылка на репозиторий с кодом:
[ВСТАВИТЬ фактический URL репозитория с кодом]

2. Ссылка на презентацию:
[ВСТАВИТЬ фактический URL PDF или страницы просмотра презентации]

3. Ссылка на прототип для проверки выполненной работы:
[ВСТАВИТЬ фактический URL работающего прототипа]

4. Ссылка на сопроводительную документацию (.docx/.pdf):
[ВСТАВИТЬ фактический URL пояснительной записки в PDF или DOCX]
```

Перед отправкой откройте каждую ссылку с учётной записи или в режиме доступа, соответствующем проверяющим, и убедитесь, что она ведёт именно к указанному артефакту. В текущей локальной копии не настроен Git remote, публичный URL репозитория или архива не зафиксирован, а прототип доступен только по локальному адресу. Для пункта 3 требуется отдельно развернуть прототип и проверить внешний адрес. Видеозапись может быть дополнительным материалом; считать её заменой ссылки на прототип можно только если это прямо разрешено правилами платформы.

Если платформа прямо разрешает вместо репозитория приложить отдельный архив, опубликуйте ZIP и приложите его `.sha256` sidecar для проверки целостности. Без такого разрешения поле 1 должно вести на репозиторий с кодом, как сформулировано в §19.
